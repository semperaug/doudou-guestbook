主题 ①｜定价权第十次换代：从"AI 能不能回本"走到"谁来定义 AI 的速度上限"

本窗口最重的一条线不是市场，是产业自律本身第一次被量化。

| 事件 | 数据 |

|---|---|

| OpenAI 首度公开预训练困惑度数据 | GPT-3.5 约 0.99 → GPT-4 约 0.91；Pachocki 称困惑度低于 0.8 时模型在网络安全与数学上出现新能力，并警告最早 2027 年 AI 可能加速自我进化、速度超过监控能力 |

| Pachocki 提议 | 以困惑度等技术指标设定行业共同限制，各家在"理解和监控模型行为的能力达到具体里程碑前不突破"；Altman 称该文是"OpenAI 一段时间以来发布的最重要内容"；微软表态支持并公布 MAI-2 评测数据 |

| 马斯克（回应 Keras 创始人肖莱） | GPU 现货价格仍在上涨、HBM 与 DRAM 到 2029 年产能基本订满、前沿模型训练算力约每 5 个月翻番；马斯克称支撑超大规模算力集群的供电、冷却与稳定运行"极其困难"，警告若全行业从投入算力到设备创收的周期累计推迟数月，仅营运资金一项就可能需额外投入数千亿美元 |

读法定案（第十次换代）：此前九次换代依次是「估值击穿 → 现金流审判 → 信用定价 → 领导权风险 → 定价定案 → 事件驱动的风险隔离定价 → 资产级独立重定价 → 融资规模与定价脱钩 → 投资回报的门槛高度」。本窗口把第 9 条「投资回报的门槛高度」推进到第 10 条「AI 发展速度的所有权」——OpenAI 提出的不是新指标，而是把"指标"变成"全行业共同上限"。这是本档案记录以来第一次出现头部实验室主动给自己设约束、且约束的度量单位被公开（困惑度 0.8 这条线可被第三方复算）。

>

与第 9 条的关系：肖莱/马斯克的"算力供给不可持续"是供给侧约束（硬件、产能、资金），Pachocki 的"困惑度限速线"是需求侧自律（能力增长速度）。两者同向但机制不同，且互不解释——同一条"AI 该慢下来"的市场叙事，本周第一次有了两个彼此独立的物理基础。

>

新增建议给 daily-brief 的字段：AI 速度约束（自律 vs 供给）——这是把第十次换代从修辞变成可复核指标的方式。

主题 ②｜管制着力点第五段的第一个执行样本：从"缺卡"到"缺许可"

BIS《应对先进半导体远程访问问题》临时最终规则 11-16 发布、11-19 生效，本窗口拿到中国侧的第一份执行反馈：

  • 管制着力点五段演进（延续本档案连续记录）：①限制谁买（云客户 ≥51% 服务来自非中国买家）→ ②限制谁什么时候拿货（约 60 万枚 H200 滞留香港）→ ③限制谁在哪里用（RASA 远程访问权）→ ④限制哪一代产品可供（Hopper 断供）→ ⑤限制供给端谁合规地下单（代工厂与封测厂一并成为管制节点）。
  • 具体条款：凡中国企业设计的先进芯片，晶圆厂与封测厂一律推定为受控 AI 芯片——手机芯片也被纳入、取消"证明非 AI 用途"豁免；境外数据中心向中国（含澳门）等 D:5 国家主体提供超 1200 万 TPP 聚合算力须逐案申请许可，存量合同须在生效后 90 天内取得许可方可续供；对印尼/马来西亚/新加坡/泰国/巴西五国进口受控 AI 芯片及服务器增加许可管控。
  • 中方回应：商务部新闻发言人 11-17 称"强烈不满、坚决反对"，称"若美方一意孤行，中方将采取反制措施"；商务部 11-18 发布《中华人民共和国两用物项出口管制清单》，系统整合多项法规规章所附清单，列明 10 类物项。
  • 关税休战进入"稀土挂钩"：美国贸易代表葛里尔 11-20 表示，明年 1 月 10 日到期的中美关税休战能否延长，取决于中国稀土供应能否满足美国所需；中方希望延长但双方未达成延长协议，目前中国核发稀土出口许可进度偏慢。特朗普 11-20 称美中正磋商"非常全面的协议"，主张对华只出售更旧型号 AI 芯片，"一块都不卖也没关系"；贝森特表示出口管制维持不变，H200 仍是中企可通过美方出口许可制度取得的最高等级 AI 芯片。
  • 另一条独立执法线：美国商务部 11-6 对进口自中国、韩国、越南的聚四亚甲基醚乙二醇作出反倾销初裁，裁定中国生产商/出口商倾销幅度 213.44%，终裁预计 2027-01-18。
第五段的真正杀伤力在于"推定"而非"清单"：一旦代工厂与封测厂被纳入管制节点，合规成本不再取决于芯片设计得多巧，而取决于下游客户是谁——这与第 1—4 段限制需求端（谁买/谁拿货/谁在哪里用/哪一代产品可供）是方向相反的作用力。前四段让海外买家买不到，第五段让海外代工厂不敢接。

>

中方筹码同步从"稀土"转向"许可体系"：11-18 两用物项清单 + 稀土出口许可节奏偏慢 = 反制工具从价格管制转为流程管制。

主题 ⑦｜开发者生态：循环式小模型、"所有 AI 代码都应开源"，以及供应链信任问题第三次浮现

GitHub 评价轴第七次定型「谁提供可被第三方独立验证的契约」，本窗口同日出现四种形态：

1. Inkling 2 Mini（Thinking Machines）——今日热榜第一。26.4B 总参 / 3.4B 激活的 MoE，中间层每 token 跑三遍（12 层 × 3 ≈ 48 层），Apache 2.0 + 1M 上下文、权重约 20GB，32GB 内存的 Apple Silicon 即可本地跑多模态；官方称在 DeepSWE v1.1 上以约 5 倍少的激活参数追平 Qwen3.8-27B。争议：Terminal Bench 仅 5.6%（Qwen 73%）、AA-Omniscience -8.6 劣于同尺寸 Qwen、社区实测会烧掉 19200 思考 token 仍写不完任务、反复 EOT 不真正调工具。评估：值得关注但暂不推荐直接上手（官方模型卡自承"相对现有开源权重模型无实质提升"）。

2. MiniMind——Trending 第 4，68.8k stars、单日 +473、连续 7 天在榜。原生 PyTorch 手写覆盖 Pretrain→SFT→LoRA→DPO→GRPO/CISPO→蒸馏→Tool Use→Agentic RL 全链路。评估：推荐，但定位是教材不是模型——"2 小时 3 块钱"实为单卡 3090 跑 1 epoch SFT 的作者自测，训练明细是预训练 1.21h + SFT 1.10h = 2.31h，且不含数据准备、调参、失败重跑和 RL 阶段；64M 模型实际水平：把万有引力归功于爱因斯坦、长江说成"珠穆朗玛峰"、大熊猫吃海产品。

3. Claude-BugHunter——Trending 连续 9 天第 1，单日 +1716 stars、18k stars。83 个 Claude Code 技能，覆盖 24 类漏洞与外部攻击面（OWASP、GraphQL/OAuth/JWT、云配置、SaaS 供应链）、M365/Okta/Cisco/Fortinet 设备红队链路与漏洞赏金报告模板。争议：README 宣称 681 个已披露报告模式、实际只有 433 个可逐条溯源；仓库描述写 82 个技能、README 写 83 个；"battle-tested" 却没给出任何具体案例或 CVE。作者自己踩过的坑：Issue #51 报告 Opus 5 在审计时静默降级到 Opus 4.8，作者的修法是把授权声明写进 skill 上下文而不是伪装成静态分析器绕过分类器；SECURITY.md 主动引用 Snyk "ToxicSkills" 研究提醒 prompt injection 风险。评估：值得关注，安装需克制——它会改 mcp.json 和 SessionStart hooks，跟生产密钥同机跑等于给自己开权限；且官方承认个人独立计划根本无法申请 Anthropic 的 Red Team Access。

4. "所有 AI 生成的代码都应开源"（Jakub Jankiewicz 提案）——HN 首页 1288 分 / 673 评论。三层论点：模型是吃开源代码长大的，专有化输出等于 "license laundering"；美国版权局 Part 2 报告 + Thaler v. Perlmutter 认定纯 AI 生成物无版权（"仅靠 prompt 不足以构成控制"）；开发者几乎不审查模型输出。反对派：Doe v. GitHub 已明确 LLM 输出不会自动继承训练语料的 GPL 传染性；AGPL 维护者 blagie 讲了自己项目被"剥掉版权声明 → 改用 LLM 克隆整个系统"的经历，"像让 LLM 重写《哈利·波特》，剧情几乎一样，对白写得一塌糊涂"。Anthropic 成了活靶子——一边在商业条款里把模型输出权利转让给客户，一边在 IPO 招股书里承认自己用 Claude Code 生成的代码可能触发 copyleft 义务、极端情况下需披露部分专有源码。

5. 供应链信任问题第三次浮现（本档案连续记录）：MiniMax 内部模型被曝破解 NIST 密码方案；OpenRouter 研究者用 200 万"金丝雀"URL 实测发现经第三方中转的提示词仍可能被访问，OpenAI 已就此与 Perplexity 呼吁联合限制；36 氪披露腾讯混元 Hy4 开源（770B 总参 / 49B 激活、约百万 token 上下文，含图像视频理解，采用自定义 Tencent Hy License）、腾讯微信视觉另开源全模态视频理解模型 WeMM-Video（2B/4B/9B 稠密 + 35B-A3B MoE）。

🆕 评价轴第七次定型的落点：前六次是自出题自判 / 自承模拟 / 不放 ISA·RTL / 作者自测 / 授权声明只给人类看 / 模型自曝退化。本窗口第七种形态是「数字对不上」——Claude-BugHunter 的 681 vs 433、82 vs 83、仓库描述与 README 不一致。但这一次的特殊性在于：作者自己公开了 Issue #51 的失败与修法，并把授权声明写进 skill 上下文——这恰恰是本档案「装第三方 skill 前先过扫描器」结论的正面样本（出问题的是模型降级，修法是让规则对模型可见，而不是绕过分类器）。

🔗 供应链风险的三条独立证据已在本窗口凑齐：①ONNX Runtime 连同 7 个仓库集体 404（依赖上游推理底座）；②OpenRouter 金丝雀实测（第三方中转泄露）；③Claude-BugHunter 的 hooks/mcp.json 写入面（第三方 skill 攻击面）。三条合起来的结论比任何单条都强：第三方组件的风险面正在从"代码质量"扩展到"运行时权限与信息流"。
